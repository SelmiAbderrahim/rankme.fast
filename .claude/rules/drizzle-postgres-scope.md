# Drizzle + Postgres Scope — Strict Rule

## MANDATORY REQUIREMENT — ZERO TOLERANCE

**Mongo is the default document store. Postgres via Drizzle is a scoped exception for relational, ordered time-series data ONLY. Money is stored as `bigint` cents. Migrations flow: edit schema → `npm run db:generate` → commit SQL → auto-apply on boot.**

## What belongs in Postgres

- **Rank history** — one row per `(siteId, keywordId, capturedAt)`, ordered time series.
- **Keywords** — the `tracked_keywords` catalog + `keyword_lookups` (cached vendor volume/difficulty).
- **Backlinks summary** (`backlink_snapshots`) and paged cache (`backlink_page_cache`).
- **Competitors** (`competitors`) — per-day snapshot.
- **Subscriptions + orders + webhook events** — the billing state machine wants relational integrity, not documents.
- **`usage_counters`** — atomic, unique `(accountId, period, metric)` increments; base cap enforcement.
- **`credit_ledger`** — signed bigint delta rows, `polar_order_id` unique on grants.
- **`vendor_cache` + `vendor_responses`** — the generic vendor data layer (`shared/vendor-cache/`): cross-user read-through cache rows keyed `(capability, operation, cacheKey)` with `expires_at` range scans, plus the append-only archive of normalized provider output ordered by `(capability, fetched_at)`. jsonb payloads are provider-normalized shapes, zod-parsed on read; private capabilities (`gsc`, `summary`, `audit`) are archive-only with `account_id` set.
- **Better Auth's own tables** (`user`, `session`, `account`, `verification`) — generated by `@better-auth/cli`; coverage-excluded.

## What stays in Mongo

- Users' domain profile (mirror of Better Auth user, keyed by the same ObjectId hex).
- Sites, audit runs, `audited_pages`, `report_snapshots`.
- Google connections (encrypted refresh tokens; per-account row).
- Communication templates state, mail delivery breadcrumbs.
- Anything shape-loose or nested-document-heavy.

If you're unsure: **default to Mongo.** Only reach for Postgres when you can name the query pattern that needs relational integrity or ordered range scans.

## Correct

```typescript
// server/src/db/schema/rank-snapshots.ts
import { pgTable, uuid, integer, timestamp, index } from "drizzle-orm/pg-core";

export const rankSnapshots = pgTable(
  "rank_snapshots",
  {
    id: uuid("id").primaryKey().defaultRandom(),
    accountId: uuid("account_id").notNull(),
    siteId: uuid("site_id").notNull(),
    keywordId: uuid("keyword_id").notNull(),
    position: integer("position"),
    capturedAt: timestamp("captured_at", { withTimezone: true }).notNull(),
  },
  (t) => ({
    perDayUnique: index("rank_snapshots_per_day_uq").on(t.siteId, t.keywordId, t.capturedAt),
  }),
);
```

```typescript
// server/src/db/schema/subscriptions.ts (money in bigint cents)
import { pgTable, uuid, text, bigint, timestamp } from "drizzle-orm/pg-core";

export const subscriptions = pgTable("subscriptions", {
  id: uuid("id").primaryKey().defaultRandom(),
  accountId: uuid("account_id").notNull().unique(),
  planSlug: text("plan_slug").notNull(),
  amountCents: bigint("amount_cents", { mode: "bigint" }).notNull(),

  status: text("status").notNull(),

```

```typescript
// server/src/db/counters.ts (atomic, unique per period+metric)
import { sql } from "drizzle-orm";
export async function incrementUsage(accountId: string, metric: string, delta: bigint) {
  await db.execute(sql`
    INSERT INTO usage_counters (account_id, period, metric, amount)
    VALUES (${accountId}, to_char(now(), 'YYYY-MM'), ${metric}, ${delta})
    ON CONFLICT (account_id, period, metric)
    DO UPDATE SET amount = usage_counters.amount + ${delta}
  `);
}
```

## Forbidden

```typescript
// WRONG — money in a JS number
amount: real("amount").notNull()          // floats are lossy for currency

// WRONG — schema edit without a migration
// (editing `subscriptions.ts` and NOT running `npm run db:generate`
//  — the CI schema-drift check fails the build)

// WRONG — direct SQL in a controller
app.get("/api/foo", async (req, res) => {
  const rows = await postgres.unsafe("SELECT * FROM ...");
});
// Route → service → drizzle query, not the raw client.

// WRONG — spreading Postgres into loose shapes
// (a "settings" JSONB column with 40 optional keys is a Mongo document,
//  not a Postgres table — move it back to Mongo)
```

## Migration workflow

1. **Edit the schema** under `server/src/db/schema/*`.
2. **`npm --prefix server run db:generate`** — drizzle-kit emits the diff SQL under `server/drizzle/`.
3. **Commit the SQL** alongside the schema change (never one without the other).
4. **Boot auto-applies.** `server.ts` awaits `runMigrations()` (`src/db/migrate.ts`, dedicated `max: 1` connection, 5 attempts with exponential backoff) BEFORE the HTTP server listens; exits non-zero if Postgres is unreachable.
5. **Tests run against PGlite.** `shared/testing/postgres.ts` executes the real generated SQL against WASM Postgres — schema drift fails tests, no separate migration lint needed.

## Data conventions

- **Money in bigint cents.** JavaScript floats are lossy; the `bigint` mode on the Drizzle column keeps arithmetic exact.
- **Timestamps as `timestamp('name', { withTimezone: true })`** — always UTC on the wire; ISO 8601 at API boundaries.
- **UUID primary keys** (`uuid('id').primaryKey().defaultRandom()`) except for Better Auth tables (which use string ids to keep parity with the Mongo mirror).
- **`notNull()` by default;** add `.default(...)` when the app-layer default is not enough.
- **One migration file per PR** — never squash after commit.

## Env

- `DATABASE_URL` — Drizzle/Postgres connection (compose: `postgres://rankme:...@postgres:5432/rankme`).
- `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` — compose provisioning; keep credentials in sync with `DATABASE_URL`.

## Validation Checklist

- [ ] New relational data is in `server/src/db/schema/`, not a Mongoose schema
- [ ] Money columns are `bigint('...', { mode: 'bigint' })`
- [ ] Every schema change ships with the generated SQL under `server/drizzle/`
- [ ] Tests run against `startMemoryPostgres()` (PGlite), not a mock
- [ ] No raw SQL from a controller — controllers → service → drizzle query
- [ ] No JSONB "settings blob" — that belongs in Mongo
